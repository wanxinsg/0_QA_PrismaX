### 6.3 P0 — History `successful_count` + Catalog 预览窗口（BE `f65ea1e` + MKT `37e8684`）



#### BE

`GET /data/downloads/history` 增加：

```sql
COUNT(*) FILTER (WHERE status = 'READY') OVER()::INTEGER AS successful_count
```

`pagination.successful_count` = READY 条数；`total_count` 仍含失败；列表不隐藏 FAILED。

#### Marketing

- `resolveSuccessfulDownloadCount(pagination)`：有合法 `successful_count` 则用；否则 **0**（`2b8a3ab` 去掉用 `total_count` 回退，避免把失败算进成功）。
- Catalog 预览：IntersectionObserver + `rootMargin`（上 1 屏 / 下 2 屏）；仅窗口内 + Hex 推荐 episode 拉 preview；`previewRequestInFlightRef` 防重复；无 IO 时 fallback 前 12 条。
- My Data 侧栏：task 搜索与列表 search 分离；**Clear all filters**。
- 另：`deploymentUrls`（dev/beta/prod origin）供 API Package 示例用 `PRISMAX_DATA_API_URL`。



#### 建议用例

完整表见 **§9**（`SPR-DH-`* / `SPR-PV-`*）。摘要：History 成功数=READY；预览仅近窗加载。

## 10. PRIS-324 补丁：Operator 开放 QA 权限（2026-08-18）

> **Commits**：`d5b2340`（前端） · `db453ed`（后端）  
> **性质**：针对 Block QA 功能的后续改善，移除对 Operator 角色的 QA 准入限制，并新增防自审校验

---

### 10.1 变更背景

PRIS-324 第一期（2026-08-17）上线 QA Blocklist 时，原有逻辑依然保留着「Operator 不得访问 QA Review」的限制（`isOperatorBlockedFromQA`）。本次补丁将该限制完全移除，Operator 现在与普通用户享有相同的 QA 审核准入资格。

---

### 10.2 后端改动（`app.py`）

**① 移除 Operator QA 禁止拦截**

```python
# 原代码（已注释）
# if _normalize_user_role(user.get("user_role")) == 'operator':
#     return None, None, (jsonify({"success": False,
#         "msg": "Operators are not eligible for QA review."}), 403)
```

`_require_qa_eligible_user` 中针对 `operator` 的 403 拦截被注释掉。Operator 用户现在可以通过 QA 资格校验，只要其 `qa_role` 在 `QA_ALLOWED_ROLES` 中，或通过普通用户的审核次数校验。

**② 新增防自审校验（`submit_upload_qa_review`）**

```python
# 查询时额外取出 upload 的 user_id
SELECT upload_id, status, user_id FROM data_uploads ...

# 提交审核时判断是否为自己的数据
upload_user_id = upload_row._mapping.get("user_id")
if upload_user_id == user["userid"]:
    return jsonify({
        "success": False,
        "msg": "You have uploaded this data. Please select a different upload to review."
    }), 403
```

由于 Operator 既可以上传数据，又可以参与 QA 审核，故在提交审核接口加入自审拦截，防止用户审核自己上传的 episode。返回 HTTP 403。
