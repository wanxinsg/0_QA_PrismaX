## 3. 按主题的测试建议

### 3.1 P0 — Robotic Data UI 隐藏 + Membership 鉴权

#### 变更要点

- FE：`ROBOTIC_DATA_UI_ENABLED = false`。侧栏 / MobileMenu 不渲染入口；访问 `/robotic-data`、`/robotic-data/:id` → `Navigate` 到 `/`。
- BE：原 `operator/admin` 角色门槛改为 **Active Data Membership Plan**。
  - **仅登录**：preview uploads、preview videos、list/revoke API keys、部分只读 My Data。
  - **需 Active Membership**：下载 UI/Manifest、My Data 写入/check、API Packages、创建 API Key、额度接口、API Key 实际下载会话等。

#### 建议用例

| ID | 场景 | 预期 |
| --- | --- | --- |
| RD-01 | 未登录 / 任意角色打开 `app-prismax-rp` | 侧栏与移动端 **无** Robotic Data 入口 |
| RD-02 | 直接访问 `/robotic-data`、`/robotic-data/123` | 重定向首页，不露出 workspace |
| RD-03 | 普通会员（有 Active plan，非 operator）调下载相关 API | 允许（不再因非 operator 被 403） |
| RD-04 | 已登录但 **无** Active membership | 下载 / 加 My Data / 建 Package / 建 API Key → **403**，文案合理 |
| RD-05 | 无会员但已登录 | preview、API Key **列表/撤销** 仍可用（按当前代码） |
| RD-06 | API Key 所属用户会员失效后请求 download session | **403**，与用户 token 路径一致 |
| RD-07 | body 带他人 `user_id` 创建 UI download | **403** `user_id does not match token` |
| RD-08 | Admin JWT 代下 | 仍走 admin 路径，不受 membership 约束（回归冒烟） |

#### 注意

- `hasRoboticDataAccess` 仍用 `operator/admin` **且** 被 feature flag 关掉；本 app 不再是订阅下载入口。若营销站 / 其他前端已切到 membership，需在对应仓库回归，本仓库只验「隐藏」。
- 与既有 Data Download 文档交叉：额度、My Data 所有权、Package 复用等逻辑本区间未重做，但鉴权入口变了，应用 **会员账号** 重跑核心下载路径。

### 3.2 P0 — QA / Operator 角色拆分（双角色）

#### 变更要点

| 字段 | 含义 |
| --- | --- |
| `users.user_role` | 账号角色：`operator` / `admin` / … |
| `users.qa_role` | QA 等级：`qa` / `senior qa` / `expert qa` / `super qa` |

#### 支持取值一览

**`qa_role`（QA 等级）** — 定义见后端 `QA_ALLOWED_ROLES` / 前端 `QA_ROLES`，比对前会做 trim + 小写 + 空白归一化：

| 值 | 说明 |
| --- | --- |
| `qa` | 基础 Validator（月度 Rotate **只**动这一档） |
| `senior qa` | Senior Validator |
| `expert qa` | Expert Validator |
| `super qa` | Super Validator |
| `NULL` / 空 | 非 QA |

Admin API `POST /api/admin/set-qa-reviewer-role` 可写入：`qa` / `senior qa` / `expert qa`（**不含** `super qa`；Admin UI 下拉里 Super QA 为 disabled）。清空时传 `null`。

**`user_role`（账号角色）** — 拆分后不再存 QA 等级；业务代码当前认的账号角色：

| 值 | 说明 |
| --- | --- |
| `operator` | Operator（申请批准时写入） |
| `admin` | Admin（权限判断 / Rotate 排除池等） |
| `NULL` / 空 | 普通用户（无账号角色） |

DB 列为可空字符串（无严格 enum）。**Legacy**：若 `qa_role` 为空但 `user_role` 仍为 `qa` / `senior qa` / `expert qa` / `super qa`，前后端会按 QA 回退读取；这不是新的账号角色写法，仅迁移窗口兼容。

同一用户可同时有 `user_role=operator` + 任意有效 `qa_role`（双角色）。

- 登录后 FE 拆成 `userRole` + `qaRole`（localStorage：`userRole` / `qaRole`）。
- Legacy：仅 `user_role='senior qa'` 且无 `qa_role` 时，仍可识别为 QA（rolling deploy）。
- **Operator + qa_role**：可进 Data Review；纯 Operator 仍拦截。
- Operator 申请：前端去掉「QA 不能申请 Operator」拦截；后端批准只设 `user_role=operator`，**不清 `qa_role`**；拒绝只在当前是 operator 时清空 `user_role`。
- Validator Rotate：读写改为 `qa_role`；踢人 `qa_role=NULL`，不碰 `user_role`；Operator **不会被自动晋升**，但 Admin 可手动授予。
- Admin QA Reviewers：读写 `qa_role`；列表展示 Operator badge；`super qa` 在 UI 下拉 **disabled**。
- `set-qa-reviewer-role` 的 `allowed_roles` 仍是 `{qa, senior qa, expert qa}`，**不含 super qa**（与列表可展示 super qa 不一致）。

#### 建议用例

| ID | 场景 | 预期 |
| --- | --- | --- |
| ROLE-01 | 纯 Operator（`qa_role` 空） | Upload 可用；Review Datasets 禁用 + 提示 Operators 不可访问 |
| ROLE-02 | Operator + `qa_role=qa` | Upload + Review 都可用；Validator 状态显示对应等级 |
| ROLE-03 | 仅 `qa_role`（`user_role` 空） | Review 可用；Account 不误显示为 Operator |
| ROLE-04 | Legacy：`user_role='Senior QA'`，`qa_role` null | 仍可进 QA；前端 `userRole` 为空、`qaRole=senior qa` |
| ROLE-05 | QA 用户申请 Operator | 前端不再 warning 拦截；批准后 **双角色** 保留 |
| ROLE-06 | 拒绝 Operator 申请（该用户同时有 `qa_role`） | `user_role` 从 operator 清掉，`qa_role` 保留 |
| ROLE-07 | Admin 给 Operator 设 `qa` / `senior` / `expert` | 成功；列表显示 QA 等级 + Operator badge |
| ROLE-08 | Admin 尝试设 `super qa` | UI 不可选；API 应 400 Invalid QA role（确认产品是否接受） |
| ROLE-09 | 清除 QA 角色 | 只清 `qa_role`；Operator 的 `user_role` 仍在 |
| ROLE-10 | Validator Rotate dry_run / apply | 只改 `qa_role`；operator 账号角色不变；operator 不进自动晋升池 |
| ROLE-11 | `/data/qa/validator-access`、progress | 响应含 `qa_role`，且 `user_role` 兼容别名等于有效 QA 角色 |
| ROLE-12 | 登出再登录 / 刷新 | `qaRole`/`userRole` 与 localStorage 一致，无串角色 |
| ROLE-13 | Expert / Super QA 选 episode 提交 review | Super 与 Expert 一样可自选 episode（后端已对齐） |

#### 数据准备建议

至少准备 5 类账号：

1. 纯 operator  
2. operator + qa  
3. 纯 qa / senior / expert  
4. legacy QA（仅旧 `user_role`）  
5. 普通会员（两边都空）

### 3.3 P0 — CDN Signed Cookie（asset 级）

#### 变更要点

- 旧：可能按 sample 多个 object 算 common prefix，或目录级 cookie → 可能授权同 upload 下兄弟文件。
- 新：`build_cdn_url_prefix` **必须恰好 1 个 object path**；API download session 对每个 asset 单独签发 cookie；顶层 `auth.scope = "asset"`。

#### 建议用例

| ID | 场景 | 预期 |
| --- | --- | --- |
| CDN-01 | 创建 API download session（多 episode / 多样本） | 每个 asset 有独立 `auth`；无 sample 级共享 cookie |
| CDN-02 | 用 asset A 的 cookie 请求同目录 asset B URL | **应失败**（安全回归核心） |
| CDN-03 | 用正确 cookie 下载对应 object | 成功；过期后失败 |
| CDN-04 | UI / Manifest 下载路径（若同样走 signed cookie） | 冒烟：能下完整文件，额度/历史正常 |
| CDN-05 | Hex / SDK / 外部脚本若仍假设 `scope=sample_or_asset` | 确认已适配 `asset`；否则记为发布阻断 |
| CDN-06 | `DATA_DERIVED_CDN_BASE_URL` 配置 | derived 预览 URL 使用配置域名（`775db74`） |

#### 注意

- 前端同日 commit `a3fc032` **没有** CDN 改动，只有分辨率检查文案；CDN 回归以 **后端 + 下载客户端** 为准。

## 5. 已知风险 / 待产品确认

1. **`super qa` 管理缺口**：列表可展示，Admin UI 禁用设置，`set-qa-reviewer-role` 也不接受。需确认 super qa 仅靠 DB/其他脚本维护是否 OK。  
2. **前后端下载入口分裂**：本 FE 隐藏 Robotic Data，BE 已对会员开放 API；务必确认真实用户走哪套 UI。  
3. **Legacy QA 迁移窗口**：依赖 `user_role` fallback；Rotate 已按 `qa_role` 查询，**未迁移的历史 base QA 可能不进 Rotate 池**。上线前应跑迁移或核对人数。  
4. **CDN 客户端兼容**：任何仍按目录/sample cookie 消费的脚本会失败或行为异常。  
5. **FE commit message 误导**：`a3fc032` 名义 CDN，实为校验文案；测试排期勿按 message 漏测后端 CDN。
